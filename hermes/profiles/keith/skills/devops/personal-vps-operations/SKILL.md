# Personal VPS Operations

Use this skill when helping Keith operate his personal VPS, Hermes profiles, Docker-hosted side projects, GitHub-backed automation, or small business websites such as Airbnb/direct-booking experiments.

## User interaction standard

- Be direct and no-BS. Lead with the practical answer.
- Give caveats clearly instead of hiding them in friendly filler.
- Push back when assumptions are wrong, risky, or legally/operationally shaky.
- Do not ask for secrets in chat. Prefer SSH deploy keys, local CLI auth, or user-run setup steps.
- If a step has already been proven in the session, say what was verified. If not tested, say so.
- For Telegram, avoid tables; use concise bullets and command blocks.

## Security defaults

1. Never request API tokens, private keys, passwords, or OAuth secrets in chat.
2. For GitHub automation, prefer repository-scoped SSH deploy keys:
   - read-only for clone/deploy jobs
   - write-enabled only for backup jobs that must push
3. Keep repositories private when they contain memory, sessions, business details, or unpublished project code.
4. Before pushing backups, verify no obvious auth material is tracked:
   ```bash
   cd /root/hermes-backup
   git ls-files | grep -Ei '(^|/)(\.env|auth\.json|nous_auth\.json|.*token.*|.*secret.*|request_dump_|logs/|cache/|bin/|node/|\.lock$|\.pid$)' || true
   git grep -Ei 'api[_-]?key|secret|token|password|private[_-]?key|BEGIN OPENSSH|BEGIN RSA|BEGIN PRIVATE' || true
   ```
5. Explain that `.gitignore` prevents matching files from being added, but does not detect secrets embedded inside allowed files like sessions, memory, config, or SQLite databases.

## Hermes profile operations

- For separate people using the same VPS, use separate Hermes profiles and preferably separate Telegram bots.
- A profile has its own `SOUL.md`, `config.yaml`, `skills/`, `memories/`, `sessions/`, `state.db`, cron config, and gateway config.
- Sharing the same Codex/OpenAI model account can still share quota/auth account even when Hermes-side profiles are separate.
- When moving from `default` to a named profile, verify the live gateway/process and config path, not just directory existence.

Useful checks:

```bash
hermes profile list
hermes -p keith config path
ps -eo pid,user,args | grep -E '[h]ermes|[g]ateway' || true
```

## GitHub backup workflow for Hermes state

See `references/hermes-github-backup.md` for the detailed pattern.

Core approach:

1. Create a local backup repo such as `/root/hermes-backup`.
2. Use a whitelist copy into the repo, not a blind copy of `~/.hermes`.
3. Exclude `.env`, auth files, token/secret-looking files, logs, caches, request dumps, locks, and runtime artifacts.
4. Include current/default profile and future named profiles.
5. Commit only when files change.
6. Push only if `origin` exists.
7. Run under system cron at the desired UTC time.

## Dockerized static web apps

For small static sites generated by AI tools:

1. Confirm whether the app is plain static HTML/CSS/JS or needs a build step such as Vite/React/Next.
2. If static, use Nginx in Docker:
   ```dockerfile
   FROM nginx:alpine
   COPY nginx.conf /etc/nginx/conf.d/default.conf
   COPY . /usr/share/nginx/html
   EXPOSE 80
   ```
3. Prefer `docker compose` with a named service, restart policy, and a non-conflicting host port.
4. Verify the container with `docker ps`, logs, and a real HTTP request.
5. Add HTTPS/domain later with Caddy/Nginx/Traefik once the app is proven.

## Airbnb/direct-booking side-project guidance

When brainstorming revenue websites for Keith's Cebu properties:

- Start with his existing advantage: five Cebu condo units, including one near Mactan Airport.
- Prefer direct-booking/lead-gen websites before generic AI tools.
- Recommend MVP flows that avoid premature payment-gateway complexity: inquiry form, Messenger/WhatsApp, manual confirmation, manual GCash deposit, clear refund/cancellation rules.
- Push back on legal/tax assumptions. Airbnb not requiring a business registration does not mean income has no tax/legal obligations.
- For Philippine payments, recommend payment gateways that support GCash only after business/verification constraints are understood; otherwise use manual GCash for MVP.

## Verification before final reply

Before saying something is done, verify with real output:

- backup: `git log --oneline -3`, `git remote -v`, manual script run, cron file, cron service
- Docker: `docker --version`, `docker compose version`, `docker run hello-world` or app-specific HTTP check
- gateway/profile: `hermes profile list`, process args, config path
- GitHub push: actual `git push` output and GitHub remote URL without secrets
